about=ZGeo opens a floating panel in which you can select a folder and recursively collect all supported spatial files. In the upper-right corner of the panel, an "EN" / "RU" button switches the interface between English and Russian without restarting QGIS; the selected language is saved. On the "Settings" tab, formats for search are checked; at the top, the buttons "Select All", "Reset All", "Vector Only", and "Raster Only" are available. The Excel format is disabled by default. Scanning is performed in the background: the name of the current file and the number of files found are displayed, and the search can be interrupted. The result is displayed as a list with name, relative path, format, coordinate system, feature count, and size; the list can be filtered. After scanning, the coordinate system, feature count and dataset size are refined on demand via the "Spatial data quality" and "Attribute data quality" tabs; the size calculation takes into account accompanying files (SHP+DBF+SHX+PRJ+CPG and others, MIF+MID, TAB+DAT/MAP/ID/IND). At the bottom of the window there is a status bar: progress of operations and the number of selected files. During scanning and long-running checks, a full-width progress bar below the status bar shows only the current check and its progress. On the "Statistics" tab, charts are built showing the distribution of files by size and by format. For a selected file, you can view the coordinate system, feature count, and attribute fields or open it in Windows Explorer. The "Copy to …" button copies selected datasets together with their sidecar files to a chosen folder, shows progress, can be cancelled, asks before replacing existing files and opens Explorer in the destination folder after a successful copy. The "Checks" button opens the "Spatial data quality" tab; checks are divided between the "Spatial data quality" and "Attribute data quality" tabs: size refinement (all formats), file readability (missing and empty files, provider open errors, vector and raster read errors), CRS refinement and checking (missing/unknown/mixed), feature count refinement, JSON compliance with GeoJSON, GeoJSON content (coordinates, ring closure, bbox and Feature/GeometryCollection structure), field name validation (non-Latin characters, length, spaces, invalid characters, truncation duplicates), field name duplicates (case-insensitive matches within a layer), dataset integrity (required files, .cpg and DBF encoding), GeoPackage/SQLite integrity (PRAGMA quick_check/integrity_check, foreign keys, required GeoPackage tables and CRS/geometry column consistency), metadata and CRS validation (missing .prj/.cpg, .aux.xml/.ovr, world files, deprecated CRS, units and axis order), geometry validity (self-intersections, unclosed rings, empty and null geometries), attribute completeness (NULL/empty strings, required fields and almost empty layers), empty fields (100% NULL columns), control and invisible characters (tabs, line breaks, carriage returns, NUL/ESC, no-break and zero-width spaces, soft hyphens, separators and the BOM in text values), attribute duplicates (full row duplicates, composite key duplicates, matches ignoring case and extra spaces and partial occurrences with percentages), blank strings (text values that are empty or consist only of spaces and behave differently from NULL in queries), leading and trailing spaces (values with leading or trailing spaces, tabs and line breaks that break comparisons and joins), double spaces inside values (two or more consecutive spaces inside a value, usually from manual input or field concatenation), numbers stored as text (text columns whose values are integers or real numbers, which compare alphabetically and cannot be used in arithmetic), mixed types in a field (text columns where numbers and text occur together, which makes Excel and SQL infer the column type differently), text encoding (mojibake values such as "ÐœÐ¾ÑÐºÐ²Ð°" instead of "Москва", read with the wrong encoding), extension and content mismatch (files whose content does not match the extension, checked by magic signatures), attribute and geometry duplicates (features that match both by all attributes and by geometry), abnormal text length (values longer than the average by more than three standard deviations, which reveals truncated dictionary fields and concatenated text), dates outside a reasonable range (date, timestamp and text values with years before 1900 or after the current year, including the zero date), suspicious field names (empty names, NULL/None/NaN names, digit-only names and technical import names such as Field1, Unnamed: 0), topology (polygon overlaps/gaps, dangling lines and line intersections), duplicate features by geometry and coordinate validation (NaN/Inf, excessively large values, swapped latitude and longitude, coordinates outside the CRS range); an "i" button next to each check opens a panel with a detailed description, actions and examples. The JSON check appears when the found files include .json or .geojson, validates the document by its type field and excludes files that are not GeoJSON; it runs before the other refinements. The optional GeoJSON check validates coordinates, ring closure, bbox and Feature/GeometryCollection structure and reports issues in the same "Issues" column. The field name check flags non-Latin characters, over-long names, spaces, invalid characters and duplicates after truncation in the "Issues" column. The field name duplicates check flags names that differ only by case within one layer. Problem checks collect their findings in the same "Issues" column, with a detailed list in the cell tooltip. After the check, the number of problem files is displayed and the "Problems Only" filter becomes available. Long-running operations can be interrupted. When exporting the file list, summary figures are added at the end of the table, statistics by format are written to a separate sheet or HTML section, and completed checks add a timing and throughput sheet or section with human-readable durations. The Export button offers Excel or a single standalone HTML file with sections for the file list, statistics, every executed check, check statistics and check timing. After saving, Explorer automatically opens with the selected file. / ZGeo открывает плавающую панель, в которой можно выбрать папку и рекурсивно собрать все поддерживаемые пространственные файлы. В правом верхнем углу панели кнопка «EN» / «RU» переключает интерфейс между английским и русским языками без перезапуска QGIS; выбранный язык сохраняется. На вкладке «Настройки» отмечаются форматы для поиска; вверху доступны кнопки «Выбрать все», «Сбросить все», «Только вектор» и «Только растр». Формат Excel по умолчанию отключён. Сканирование выполняется в фоне: показываются имя текущего файла и число найденных, поиск можно прервать. Результат выводится списком с именем, относительным путём, форматом, системой координат, количеством элементов и размером; список можно фильтровать. После сканирования система координат, количество элементов и размер набора данных уточняются на закладках «Качество пространственных данных» и «Качество атрибутивных данных»; размер рассчитывается с учётом сопутствующих файлов (SHP+DBF+SHX+PRJ+CPG и другие, MIF+MID, TAB+DAT/MAP/ID/IND). Внизу окна расположена статусная строка: ход операций и количество выбранных файлов. На вкладке «Статистика» строятся диаграммы распределения файлов по размеру и по формату. Для выбранного файла можно посмотреть систему координат, количество объектов и атрибутивные поля либо открыть его в проводнике Windows. Кнопка «Скопировать в …» копирует выбранные наборы вместе с сопутствующими файлами в выбранную папку, показывает прогресс, позволяет отменить операцию, запрашивает подтверждение перед заменой существующих файлов и после успешного копирования открывает проводник в папке назначения. Кнопка «Проверки» открывает закладку «Качество пространственных данных»; проверки разделены между закладками «Качество пространственных данных» и «Качество атрибутивных данных»: уточнение размера (все форматы), читаемость файлов (отсутствующие и пустые файлы, ошибки открытия провайдеров, ошибки чтения вектора и растра), уточнение и проверка системы координат (отсутствующая/неизвестная/смешанная), уточнение количества элементов, проверка JSON, проверка GeoJSON (координаты, замкнутость колец, bbox и структура Feature/GeometryCollection), имён полей (нелатинские символы, длина, пробелы, недопустимые символы, дубли после усечения), дублей имён полей (совпадения без учёта регистра в одном слое), целостности набора (обязательные файлы, .cpg и кодировка DBF), целостности GeoPackage/SQLite (PRAGMA quick_check/integrity_check, внешние ключи, обязательные таблицы GeoPackage и согласованность CRS и геометрических колонок), метаданных и CRS (отсутствие .prj/.cpg, .aux.xml/.ovr, файлов привязки, устаревшие CRS, единицы и порядок осей), валидности геометрий (самопересечения, незамкнутые кольца, пустые и null-геометрии), заполненности атрибутов (NULL, пустые строки, обязательные поля и почти пустые слои), полей-пустышек (100% NULL), топологии (наложения и разрывы полигонов, висячие линии и пересечения линий), дублей объектов по геометрии и координат (NaN/Inf, слишком большие значения, перепутанные широта и долгота, координаты вне допустимого диапазона CRS). Проверка GeoJSON анализирует координаты, замкнутость колец, bbox и структуру Feature/GeometryCollection и показывает замечания в колонке «Проблемы». Справа от каждой проверки находится кнопка «i», открывающая панель с подробным описанием и примерами. Проверка имён полей отмечает нелатинские символы, слишком длинные имена, пробелы, недопустимые символы и дубли после усечения в колонке «Проблемы». Проверка дублей имён полей ищет имена, различающиеся только регистром, в пределах одного слоя. Проверки проблем складывают замечания в ту же колонку «Проблемы», подробности видны в подсказке к ячейке. После проверок показывается количество проблемных файлов и доступен фильтр «Только проблемные». Длительные операции можно прервать. При экспорте списка файлов в конце таблицы добавляются итоговые цифры, статистика по форматам записывается отдельным листом или разделом HTML, а для выполненных проверок добавляется лист или раздел с временем и скоростью обработки. Кнопка «Экспорт» предлагает Excel или один автономный HTML-файл с разделами по списку файлов, статистике, каждой выполненной проверке, статистике проверок и времени проверки. После сохранения проводник автоматически открывается с выделенным файлом.
